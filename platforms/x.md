# X 格式与合规要点

本页只说明怎么写草稿和怎么人工运营。不提供自动发帖、自动私信、自动批量关注或抓取私信的方法。

## 内容形态

- **单帖**：以当时平台字数上限为准（常见为 280 个字符；若用户账号有更长上限，按用户实际情况写，并在草稿中注明假设的上限）。中英文混排时先写短稿，再检查是否超限。
- **串帖（thread）**：适合把一条新闻拆成「事实 → 影响 → 可执行建议 → CTA」。每条都能相对独立读懂，第一条承担钩子。建议 3–6 条，不要写成没有分段的长文。
- **引用 / 转帖**：优先引用原始报道或官方公告，再补充你的解释。不要去掉关键限制条件。
- **图片**：如需封面或信息图，文案与图中文字不要互相矛盾；图中文字同样不能虚构数据。

## 结构建议

1. 第一条：具体事实或具体问题 + 为何与读者有关。
2. 中间条：出处、限制条件、对目标用户的含义。每条尽量附上可核对的来源。
3. 最后一条：领取钩子或主页指引，例如「入门清单的领取方式写在我的主页和置顶帖」。在 X 上不强调「评论扣词」，因为私信和回复的滥用很容易触发限制。
4. 需要讨论时，可以提一个真正想听到回答的问题，而不是为了刷回复。

## Bio 与置顶

- **简介**：一句话说清你是谁、给谁看、资料在哪里。预留链接位置（主页链接、新闻通讯或公众号说明页）。
- **置顶帖**：固定说明免费资料是什么、如何领取、你不提供什么。

## CTA 写法

推荐：指向置顶帖、主页链接、公开的资料页；邀请有具体问题的人自行留言，由你人工回复。

不推荐：批量私信陌生账号、自动回复所有提及、互关互赞、伪造互动数字。

## 合规要点

- 遵守 X 的规则与当地法律，不发布违法内容和误导性广告。
- 不自动私信、不自动批量关注或取关、不抓取他人未公开数据。
- 转发新闻必须可追溯；不把示例数据或未核对传言写成「刚刚发生」。
- 草稿由用户在官方客户端手动发布或使用官方账号自带的定时功能。本技能不直接调用发帖接口，也不编写群发脚本。
